# No.1 Sports

## เปิดใช้งานในเครื่อง Windows / XAMPP

เปิด MySQL ใน XAMPP แล้วเปิด terminal สองหน้าต่างที่โฟลเดอร์โปรเจกต์:

1. `npm.cmd run dev:api` เปิด PHP ของ XAMPP ที่พอร์ต 8080 (มีไดรเวอร์ MySQL)
2. `npm.cmd run dev` เปิดหน้าเว็บ แล้วเข้า URL ที่ Vite แสดง เช่น `http://127.0.0.1:5173`

ใช้ `.env.local` ที่ตั้ง `VITE_PREVIEW_MODE=false` สำหรับระบบจริง PHP ต้องเขียนโฟลเดอร์ session ที่กำหนดใน php.ini ได้ อย่าเปิดเฉพาะ Vite เพราะ API ต้องทำงานด้วย หากพอร์ตถูกใช้งานอยู่ ให้ใช้เซิร์ฟเวอร์เดิมหรือปิด process เดิมก่อนเปิดใหม่

ตรวจสอบด้วย `npm.cmd test` และ `npm.cmd run build` การทดสอบครอบคลุม API ผิดรูปแบบ การเชื่อมต่อขัดข้อง CSRF และการป้องกัน polling ซ้อนกัน เมื่อโหลดข้อมูลหลักไม่สำเร็จ เว็บจะลองโหลดใหม่ในรอบอัปเดตถัดไป คำขอสร้างการจองจะไม่ถูกส่งซ้ำอัตโนมัติ

เว็บไซต์จองสนามฟุตบอลภาษาไทย สร้างด้วย Vue 3 + PHP + MySQL จัดการฐานข้อมูลผ่าน phpMyAdmin

## คู่มือสำหรับผู้รับโฟลเดอร์ไปใช้งาน

### เปิดใช้งานแบบเร็วบน Windows / XAMPP

1. ติดตั้ง Node.js, XAMPP และเปิด `Apache` กับ `MySQL` ใน XAMPP
2. เปิด phpMyAdmin ที่ `http://localhost/phpmyadmin` แล้วสร้างฐานข้อมูลชื่อ `no1_sports` โดยใช้ `utf8mb4`
3. Import ไฟล์ `database/schema.sql` ลงฐานข้อมูลที่สร้างใหม่
4. ถ้าเป็นฐานข้อมูลเดิมที่สร้างก่อนมีระบบโปรโมชั่น ให้รัน `database/migration_promotion.sql` เพิ่มหนึ่งครั้ง
5. ตรวจ `server/config.php` ให้ชื่อฐานข้อมูล ผู้ใช้ และรหัสผ่านตรงกับเครื่อง หากยังไม่มีไฟล์นี้ให้คัดลอกจาก `server/config.example.php`
6. เปิด terminal ที่โฟลเดอร์โปรเจกต์ แล้วติดตั้งแพ็กเกจ:

	```powershell
	npm.cmd ci
	```

7. เปิด terminal หน้าหนึ่งสำหรับ API:

	```powershell
	npm.cmd run dev:api
	```

8. เปิด terminal อีกหน้าสำหรับหน้าเว็บ:

	```powershell
	npm.cmd run dev
	```

9. เปิด URL ที่ Vite แสดง เช่น `http://127.0.0.1:5173` โดยต้องเปิด API ไว้พร้อมกัน
10. สร้างบัญชีแอดมินด้วยคำสั่ง `C:\xampp\php\php.exe server/bin/create-admin.php` แล้วกรอกชื่อ อีเมล และรหัสผ่านอย่างน้อย 12 ตัวอักษร

### การตั้งค่าครั้งแรกของแอดมิน

1. เปิดเว็บไซต์แล้วเข้าสู่ระบบด้วยบัญชีแอดมิน ระบบจะพาไปหน้า `#admin` อัตโนมัติ
2. แท็บ **สนามและราคา**: เพิ่มสนาม ใส่ราคา คำอธิบาย รูป และเลือกเปิดให้จอง
3. แท็บ **ตั้งค่าเว็บไซต์**: ใส่ที่อยู่ ช่องทางติดต่อ สิ่งอำนวยความสะดวก กติกา และข้อความโปรโมชั่น
4. ตั้งโปรโมชั่นได้ที่ช่อง **โค้ดโปรโมชั่น** และ **ส่วนลดเปอร์เซ็นต์** เช่น `No1Sports` กับ `20` แล้วกดบันทึก
5. อัปโหลด QR รับเงินจริง ตรวจชื่อบัญชีให้ตรงกับบัญชีธนาคารก่อนเปิดรับจอง
6. ตรวจการตั้งค่าทั้งหมด แล้วติ๊ก **เปิดรับจองสนาม** จากนั้นกดบันทึก

การปิดโปรโมชั่นทำได้โดยล้างโค้ด หรือใส่ส่วนลดเป็น `0` ลูกค้าจะยังเห็นข้อความประชาสัมพันธ์ได้ แต่ใช้โค้ดลดราคาไม่ได้

### วิธีใช้งานสำหรับลูกค้า

1. เปิดหน้าเว็บและเลือกวันที่ สนาม และระยะเวลา
2. เลือกช่วงเวลาที่แสดงว่า **ว่าง**
3. หากมีโปรโมชั่น ให้กรอกโค้ดในช่องโค้ดโปรโมชั่น ระบบจะแสดงยอดหลังลดทันที
4. สมัครสมาชิกหรือล็อกอินด้วยอีเมลหรือเบอร์โทร
5. กดยืนยันการจอง ระบบกันเวลาไว้ 15 นาทีและพาไปหน้าชำระเงิน
6. โอนเงินตามบัญชีหรือ QR ที่แอดมินตั้งไว้ แล้วแนบสลิป
7. รอแอดมินตรวจสอบ เมื่อผ่านแล้วดูตั๋ว QR ได้ที่เมนู **ตั๋วของฉัน**
8. แสดง QR ให้แอดมินสแกนก่อนเข้าสนาม

### วิธีใช้งานสำหรับแอดมิน

1. ล็อกอินด้วยบัญชีแอดมินจากปุ่มเข้าสู่ระบบเดียวกับลูกค้า ระบบแยกหน้าให้อัตโนมัติตามสิทธิ์
2. ดูรายการจองจากแท็บ **รายการจอง** และค้นหาด้วยชื่อ เบอร์โทร หรือรหัสจอง
3. เปิดรายการที่สถานะ **รอตรวจสลิป** ตรวจยอดเงินจริง ชื่อผู้รับ และเวลาบนสลิป
4. กด **ยืนยันเงินเข้า** หรือ **ไม่ผ่าน** พร้อมระบุเหตุผล
5. เมื่อถึงเวลา เปิดรายการแล้วกด **ยืนยันเช็คอิน** หลังตรวจ QR ของลูกค้า
6. เมื่อจบการใช้สนาม กด **ยืนยันหมดเวลา** หากจำเป็น ระบบจะเปลี่ยนสถานะอัตโนมัติเมื่อมีคำขอ API หรือทำงาน maintenance
7. ประวัติที่จบแล้ว ยกเลิกแล้ว หมดอายุ หรือไม่ผ่าน สามารถลบข้อมูลถาวรได้จากปุ่ม **ลบประวัติ**

### ลำดับการทำงานของระบบ

```text

		  |
		  v
กรอกโค้ดโปรโมชั่น (ถ้ามี) -> เซิร์ฟเวอร์ตรวจโค้ดและคำนวณยอดจริง
		  |
		  v

		  |

	|                    |
	v                    v
```

ระบบคำนวณราคาและส่วนลดที่ฝั่งเซิร์ฟเวอร์เสมอ ลูกค้าไม่สามารถแก้ราคาเองได้ การจองที่ยังรอตรวจสลิปจะไม่ถูกคืนเวลาอัตโนมัติเพื่อป้องกันกรณีโอนเงินจริงแล้ว

## สถานะของงาน

- หน้าแรกแนะนำสนาม เลือกวัน เวลา ระยะเวลา และแสดงช่วงที่เต็ม
- สมัครสมาชิกด้วยอีเมลหรือเบอร์โทรพร้อมรหัสผ่าน (ยังไม่ใช่การยืนยันอีเมลหรือ SMS OTP)
- แยกสิทธิ์แอดมิน/ลูกค้าที่ PHP ทุกคำขอ ลูกค้าแก้ role เองไม่ได้
- จองโดยล็อกแถวสนามใน transaction ป้องกันการจองซ้อน คำนวณราคาบนเซิร์ฟเวอร์
- โอนเข้าบัญชี **กสิกรไทย 164-8-13740-7 ภาวนียา หาญศึก** และแนบสลิป
- แอดมินอัปโหลด QR รับเงินที่ได้จากธนาคารจริงได้ ระบบไม่ได้สร้าง QR รับเงินจากเลขบัญชีเอง
- แอดมินตรวจสลิปและยอดเข้าบัญชีจริงก่อนยืนยัน ไม่ได้เชื่อมธนาคารหรือตรวจสลิปอัตโนมัติ
- ตั๋วระบุรหัส ชื่อ สนาม วันเวลา พร้อม QR สุ่ม 256 บิตหลังชำระผ่าน
- สแกนผ่านกล้องหรือกรอกรหัสตั๋ว แล้วกดยืนยันเช็คอิน ป้องกันใช้ซ้ำ
- เช็คอินได้ก่อนเริ่ม 30 นาทีจนถึงสิ้นสุด แอดมินกดหมดเวลาได้ หรือระบบเปลี่ยนเมื่อถึงเวลาสิ้นสุด
- ตารางและสถานะอัปเดตทุก 5 วินาที ไม่ใช่ WebSocket
- แอดมินจัดการสนาม ราคา รูป โปรโมชั่น อุปกรณ์ ที่อยู่ ช่องทางติดต่อ และดูประวัติการจอง/การดำเนินการ

ลิงก์ Sites เป็น **โหมดตัวอย่างส่วนตัว** เท่านั้น ไม่รับข้อมูลส่วนบุคคล ไม่รับจอง และไม่รับเงิน ภาพสนาม/สนาม 3 รายการ/ราคา/ตั๋วตัวอย่างไม่ใช่ข้อมูลจริงของร้าน ชุดติดตั้ง PHP ไม่มีสนามตัวอย่างและปิดรับจองไว้จนกว่าแอดมินจะตั้งค่า

## ติดตั้งบนโฮสติ้ง PHP/MySQL

ต้องมี PHP 8.2 ขึ้นไปพร้อม `pdo_mysql`, `mbstring`, `fileinfo`, `session` และ MySQL 8 หรือ MariaDB ที่รองรับ InnoDB ใช้รุ่นที่ผู้ให้บริการยังออกอัปเดตความปลอดภัย เปิด HTTPS สำหรับรับข้อมูลสมาชิกและใช้กล้อง

1. แตก **No1-Sports-Install.zip** หากใช้ซอร์ส ให้ `npm ci` แล้ว `npm run package` เพื่อสร้างโฟลเดอร์ `release/` ก่อน
2. อัปโหลดโฟลเดอร์ `server` ไปยังพื้นที่เว็บไซต์ และกำหนด DocumentRoot ให้ชี้ที่ **server/public** เท่านั้น `config.php`, `bootstrap.php`, `storage` ต้องอยู่ภายนอก DocumentRoot
3. สร้างฐานข้อมูล UTF-8 ใน phpMyAdmin แล้ว Import `database/schema.sql` ลงฐานข้อมูลว่าง สร้างผู้ใช้ฐานข้อมูลสำหรับเว็บที่เข้าถึงเฉพาะฐานข้อมูลนี้ ห้ามใช้ root ในระบบจริง หากเป็นฐานข้อมูลเดิมให้รัน `database/migration_promotion.sql` เพิ่ม
4. คัดลอก `server/config.example.php` เป็น `server/config.php` ใส่ชื่อฐานข้อมูล ผู้ใช้ รหัสผ่านและโฮสต์ ตั้ง `secure_cookies=true` เมื่อใช้ HTTPS
5. ให้ PHP เขียน `server/storage` ได้ ไฟล์สลิปไม่ควรอ่านผ่าน URL โดยตรง ตั้ง `upload_max_filesize=5M`, `post_max_size=6M`, `display_errors=Off` (.user.ini จัดไว้แล้ว; ถ้าโฮสติ้งไม่อ่านไฟล์นี้ให้ตั้งผ่านแผงควบคุม)
6. สร้างแอดมินทาง terminal ด้วย `php server/bin/create-admin.php` แล้วกรอกชื่อ อีเมล และรหัสผ่าน **ไม่มีแอดมินหรือรหัสผ่านเริ่มต้น** หากโฮสติ้งไม่มี terminal ให้ผู้ดูแลรันสคริปต์นี้หรือทำตามวิธี phpMyAdmin ด้านล่าง
7. เข้าหน้า `/#admin` ด้วยบัญชีแอดมิน เพิ่มสนาม/ราคา/รูปจริง ใส่ที่อยู่ ช่องทางติดต่อ อุปกรณ์และเงื่อนไข อัปโหลด QR ธนาคารที่ชื่อผู้รับตรงกัน
8. ทดสอบเส้นทางสมัคร → จอง → โอนยอดทดสอบตามที่เจ้าของอนุญาต → แนบสลิป → แอดมินยืนยัน → รับตั๋ว → เช็คอิน ก่อนติ๊ก “เปิดรับจองสนาม” สำหรับลูกค้าจริง ไม่ได้มีการโอนเงินทดสอบในงานนี้

### สร้างแอดมินผ่าน phpMyAdmin ถ้าไม่มี terminal

หลังติดตั้งเว็บ ให้เจ้าของสมัครบัญชีของตนผ่านหน้าเว็บก่อน จากนั้นล็อกอิน **phpMyAdmin** ด้วยสิทธิ์ฐานข้อมูล เปิดตาราง `users` ตรวจอีเมลและชื่อให้ตรงกับบัญชีเจ้าของ แก้คอลัมน์ `role` ของแถวนั้นจาก `customer` เป็น `admin` แล้วออกจากระบบเว็บและเข้าใหม่ อย่าเปลี่ยนสิทธิ์ให้บัญชีที่ไม่รู้จัก ไม่ต้องแก้รหัสผ่านหรือใส่รหัสผ่านแบบข้อความลงฐานข้อมูล

### งานบำรุงรักษา

ตั้ง cron ทุกนาทีให้รัน `php /absolute/path/server/bin/maintenance.php` เพื่อคืนรายการที่หมดเวลาชำระและจบการใช้สนามอัตโนมัติ แม้ไม่มีใครเปิดเว็บ API จะตรวจเงื่อนไขเหล่านี้ซ้ำเมื่อมีคำขอด้วย

สำรองฐานข้อมูลและ `server/storage` ร่วมกัน เก็บสลิปตามระยะเวลาที่ธุรกิจกำหนด สลิปที่ถูกปฏิเสธหรือการโอนหลังหมดเวลาจองต้องให้ผู้ดูแลติดต่อผู้จองเรื่องคืนเงินนอกระบบ ยังไม่มีการคืนเงินอัตโนมัติ บัญชีแอดมินควรเป็นของพนักงานแต่ละคนเพื่อให้ประวัติระบุตัวผู้ดำเนินการได้

## ทดลองด้วย XAMPP บน Windows

1. เปิด MySQL ใน XAMPP สร้างฐานข้อมูล `no1_sports` ใน phpMyAdmin และนำเข้า SQL ตามขั้นตอนด้านบน
2. คัดลอก config ใส่การเชื่อมต่อ MySQL ของเครื่อง ตั้ง `secure_cookies=false` เฉพาะ localhost HTTP
3. เปิด terminal ที่โฟลเดอร์โปรเจกต์ รัน `C:\xampp\php\php.exe -S 127.0.0.1:8080 -t server/public`
4. หากใช้ชุด Install ที่คอมไพล์แล้ว เปิด `http://127.0.0.1:8080` ได้เลย หากใช้ซอร์ส ตั้ง `.env.local` เป็น `VITE_PREVIEW_MODE=false` แล้ว `npm ci` และ `npm run dev` เปิด URL ที่แสดง
5. สร้างบัญชีแอดมินตามวิธีด้านบน localhost ไม่ได้ทำให้ลูกค้านอกเครื่องเข้าถึงได้ การเปิดสาธารณะต้องใช้โฮสติ้ง HTTPS

## สำหรับนักพัฒนา

```text
src/                  Vue UI และการติดต่อ API
server/public/api/    PHP API ที่เปิดให้เว็บเรียก
server/bootstrap.php  PDO, session, role checks, uploads, rate limits
server/bin/           สร้างแอดมิน / งานบำรุงรักษา
server/storage/       สลิปและภาพที่อัปโหลด (อยู่นอก web root)
database/schema.sql   นำเข้าผ่าน phpMyAdmin
```

`npm run dev` และ `npm run build` เชื่อม PHP/MySQL จริงโดยปริยาย โหมดตัวอย่างต้องตั้ง `VITE_PREVIEW_MODE=true` อย่างชัดเจน ไม่ใส่รหัสผ่านฐานข้อมูลในตัวแปร VITE การ build เพื่อเผยแพร่ PHP ทำผ่าน `npm run package` ได้ โดยไม่รวม config จริงหรือไฟล์อัปโหลด

ตรวจการเชื่อมต่อและตารางด้วย `C:\xampp\php\php.exe server/bin/check-database.php` ทดสอบสถานะกับ MySQL ด้วย `C:\xampp\php\php.exe scripts/database.test.php` ซึ่งย้อนกลับข้อมูลทดสอบด้วย transaction หลังจบ การชำระเงินใช้โอนพร้อมแนบสลิปและให้แอดมินตรวจยอดจริงก่อนอนุมัติ รายการที่ชำระแล้วจะหมดเวลาเมื่อสิ้นสุดการจอง รวมกรณีไม่ได้เช็คอิน ส่วนรายการรอตรวจสลิปยังคงรอตรวจเพื่อไม่คืนเวลาของผู้ที่โอนแล้ว การกดจบก่อนเวลายังคงกันช่วงจองเดิมไว้ ปรับสถานะอัตโนมัติเมื่อมีคำขอ API หรือเรียก `server/bin/maintenance.php` ผ่านงานตามเวลา

ข้อมูลเวลาใช้ Asia/Bangkok เปิด 09:00–23:00 จองล่วงหน้าได้ 90 วัน กันเวลารอชำระ 15 นาที ลูกค้ามีรายการรอชำระ/รอตรวจรวมได้สูงสุด 3 รายการ สลิปที่ส่งแล้วรอแอดมินตรวจและไม่หมดอายุอัตโนมัติเพื่อไม่คืนช่วงเวลาที่โอนแล้วให้ผู้อื่น

ใช้ session HttpOnly/SameSite, CSRF token, password_hash/password_verify, prepared statements และการตรวจชนิดไฟล์จริง ภาพสลิปเข้าถึงได้เฉพาะแอดมิน ตารางว่างไม่ส่งชื่อหรือข้อมูลติดต่อของลูกค้าออกมา อีเมล/เบอร์โทรเป็นชื่อบัญชี ยังไม่ได้พิสูจน์ความเป็นเจ้าของ หากต้องการ OTP หรือกู้รหัสผ่าน ต้องเชื่อมผู้ให้บริการส่งอีเมล/SMS เพิ่ม

## การตรวจสอบที่ทำแล้ว

ผ่านการคอมไพล์ Vue, เรนเดอร์หน้า home/bookings/admin และ 8 หน้าต่างแบบ server render, ตรวจไวยากรณ์ PHP และ 40 การตรวจ API กับฐานข้อมูลทดสอบ MariaDB แยก รวมการแย่งจองพร้อมกันจาก PHP สอง process, ราคาฝั่งเซิร์ฟเวอร์, ป้องกันเข้าถึงข้ามผู้ใช้, CSRF, ไฟล์ปลอม, สลิปซ้ำ, ยืนยันชำระ, QR lookup, เช็คอินซ้ำ, หมดเวลาชำระ, ยกเลิก และประวัติ

ยังไม่ได้ทดสอบกล้องกับอุปกรณ์จริง การโอนเงินจริง หรือการเชื่อมโฮสติ้งจริง ไม่ได้ทำ browser visual QA ส่วน WebMCP ที่เลือกวันจองเพิ่มไว้เป็นตัวช่วยแบบ optional ยังไม่มีบริบท WebMCP สำหรับตรวจสอบการลงทะเบียน
